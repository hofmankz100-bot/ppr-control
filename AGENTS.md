# Постоянные правила изменения ППР Контроль

Инструкция пользователя, подтверждена 2026-09-08. Применять при каждом изменении этого проекта, включая новые задачи и работу агентов.

## Исправлять существующую логику, не писать поверх неё

1. Сначала найти действующую реализацию функции и все связанные вызовы, обработчики и проверки на клиенте и сервере.
2. Неправильную логику исправить на месте либо заменить новой. После замены удалить ставшие ненужными дубли, обработчики и ветви именно этой функции; не оставлять две конкурирующие реализации.
3. Не добавлять повторные функции, поздние переопределения, дополнительные обработчики или обходные слои для маскировки старой ошибки. Не раздувать код таким способом.
4. Старый по возрасту код не обязательно неправильный. Сохранять рабочие части и необходимые пути совместимости с сохранёнными данными и установленными клиентами. Удалять код только после проверки зависимостей. Если старый путь временно необходим, объяснить причину.

## Сохранность данных и границы изменений

- Менять только неправильную логику запрошенной функции. Расширение на соседние функции требует согласования с пользователем.
- Сохранять рабочее поведение приложения, журналы, фотографии, записи и ручные номера групп. Рефакторинг кода не разрешает удаление или очистку производственных данных.
- Для удаления данных требуется отдельное явное согласие пользователя. Не выполнять массовую очистку в рамках исправления кода.
- Сохранять чужие и ранее существовавшие изменения в рабочей папке.

## Проверка и результат

- Проверять регрессии, отсутствие двойных действий и сохранность существующих записей.
- Перед публикацией просматривать diff и запускать относящиеся к изменению тесты; после публикации проверять фактически работающую версию.
- В итоговом ответе кратко указывать заменённую неправильную логику, удалённые дубли и результаты проверок. Не объявлять исправление опубликованным без проверки развёртывания.
