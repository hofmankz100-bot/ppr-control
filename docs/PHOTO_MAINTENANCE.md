# Сжатие старых фотографий

Обработчик не запускается вместе с сервером. Публикация кода сама по себе не
изменяет фотографии. Сначала восстановить доступность сервера и PRIMARY.

Только аудит размеров (без записи и без декодирования всех фотографий):

```sh
node tools/compress-existing-photos.js --limit 0
```

Первая ограниченная партия:

```sh
node tools/compress-existing-photos.js --apply --limit 20
```

После проверки результата обработать остальные записи (`--after` принимает
точное `lastFile` из отчёта; `--limit 0` означает весь остаток). Повторный запуск
не пережимает уже обработанные фотографии, а проверяет публикацию кэша/зеркал.

Оригиналы сохраняются в отдельной **постоянной WAL-logged** таблице
`public.ppr_photo_originals` основной базы. Временные файлы Render не считаются
резервной копией. Сохранение оригинала, чтение его обратно с проверкой SHA-256
и замена фото выполняются одной транзакцией. При несовпадении текущей фотографии
с ожидаемой замена отменяется. Связи в журналах, имена файлов и MIME сохраняются.

Восстановление одного конкретного файла:

```sh
node tools/compress-existing-photos.js --apply --restore FILE_NAME.jpg
```

Восстановление откажется заменять фотографию, если она изменилась после сжатия.
Оригиналы автоматически не удаляются. Их хранение означает, что уменьшение
рабочих фото **не равно освобождению общего места в базе**. До начала записи
проверяется бюджет новых оригиналов 128 MiB и запас до 900 MiB всей базы;
перед каждым фото проверка повторяется. Для более крупной базы требуется
отдельный план внешнего архивирования, а не снятие защитных ограничений.

JPEG/WebP больше 250 KiB уменьшаются до 1200 px с сохранением пропорций.
PNG оптимизируется без изменения пикселей/альфы. PDF, анимации, повреждённые
изображения и недостаточная экономия пропускаются. Обработка поштучная;
кэш sharp отключён, число потоков ограничено одним.

Старые встроенные `data:image` внутри JSON этим инструментом не изменяются.
Уже закэшированные браузером фотографии могут оставаться большими до очистки
или истечения HTTP-кэша. Недоступное зеркало отмечается в отчёте; после его
восстановления нужно повторить проверку. Не выполнять SQL VACUUM FULL или
удаление оригиналов в рамках этой процедуры.
