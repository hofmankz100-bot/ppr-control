# Окна и длинные экраны на телефоне

Аудит выполнен по `app.js`, `index.html`, `styles.css` и всем исходным модулям. Исправления окон вынесены в `modules/mobile-dialogs.css`; оформление сварочных и токарных заявок — в отдельные `modules/production-work-ui.js` и `modules/production-work-ui.css`.

Цель: начало формы и последние действия доступны на узком или низком экране. Высота окна учитывает `dvh` и безопасные отступы устройства. Сохранены горизонтальная прокрутка таблиц и карточек, обычная прокрутка страниц, ограничения доступа и печать.

`modules/director.js`, `modules/compressor.js`, `modules/shgrp.js` и `modules/receiver.js` содержат вспомогательные функции и отдельные модальные элементы не создают. Печатные popup — отдельные HTML-документы; новый файл CSS в них не подключается. Все новые правила ограничены `@media screen`, поэтому не изменяют печатный формат A4, PDF и специальные печатные ограничения высоты.

## Браузерная проверка

`e2e/mobile-dialogs.spec.js` открывает окна настоящими кнопками после настоящего входа на отдельном сервере. Длинные данные задаются только при создании изолированной тестовой БД. DOM окон не подставляется и функции приложения напрямую не вызываются.

Проверяются portrait `390×640`, низкий landscape `740×320` и годовой ППР `1100×360`. Для длинных окон проверяются границы viewport, прокрутка, достижимость последнего элемента и работа отмены/возврата. В Android Chromium используется настоящий вертикальный жест через браузерный протокол `Input.dispatchTouchEvent`, в desktop Chromium — wheel-событие. Playwright не предоставляет swipe/wheel для mobile WebKit: там используется DOM `scrollBy`, проверка разрешённого `overflow`, положения содержимого и настоящих кнопок. Этот профиль не доказывает физический свайп на iPhone.

Проверка кнопки сохранения журнала использует hit-test без применения изменений. QR-сценарий сохраняет тестовое замечание в своей БД, затем проверяет повторный QR и выбор причины остановки. Дополнительно проверяются ошибки пустых полей при закрытии/печати простоя, публичная форма наёмного сотрудника и успешное подтверждение штатной смены по действительному QR тестового сервера. Подтип отказа доступа к закрытию простоя проверен по общей структуре и CSS; отдельный переход через UI в этот подтип не заявляется.

Команды:

```sh
npm run build
npx playwright test e2e/mobile-dialogs.spec.js
```

Те же сценарии выполняются в настроенных проектах desktop Chromium, Android Chromium и iPhone WebKit. Локальный профиль использует отдельные JSON-файлы; PostgreSQL-профиль включается только через явно заданный `PPR_E2E_POSTGRES_URL` и создаёт отдельную БД каждому тесту, как описано в `BROWSER_TESTING.md`.

Проверка 6 сентября 2026 года: все 12 сценариев окон × 3 браузерных профиля прошли. Для версии `v788-mobile-panels-1`, коммит `9f1ddeb`, общая CI-матрица получила 113 passed и один ранее существовавший skip в каждом хранилище (JSON и PostgreSQL). Пропущен сценарий навигации без сети в мобильном WebKit; сохранение очереди при потере сети проверяется отдельными сценариями. Интеграционные проверки реальной PostgreSQL также прошли (16 проверок). Ошибки страницы не фильтруются.

На рабочем сайте дополнительно проверены сварка, токарка и посещаемость при размерах 390×640 и 740×320: перелистывание карточек, внутренняя вертикальная прокрутка, доступность последней кнопки, закрытие формы и повторное открытие окна с возвращением на главную. Производственные записи при ручной проверке не изменялись. Для годового листа тест ожидает завершения серверного заполнения перед измерением высоты: иначе новая разметка могла заменять лист во время жеста.

Эмуляция размеров и браузеров не является проверкой физических телефонов или реальной клавиатуры. Финальная ручная проверка на устройстве: открыть длинную форму, вызвать клавиатуру у последнего поля, прокрутить пальцем в обе стороны и нажать отмену/сохранение. Для журналов также проверить горизонтальный свайп и печать. Сканер отдельно проверить с разрешённой камерой: автоматический тест эмулирует отказ доступа к камере, а реальное чтение PNG покрывает `e2e/qr-photo.spec.js`.
