# ППР Контроль

Производственная PWA для ППР, журналов оборудования, QR-обходов,
замечаний, простоев, нарядов-допусков и контроля сотрудников.

## Требования

- Node.js 18 или новее;
- npm;
- PostgreSQL — только для проверки серверного режима. Без строк подключения
  сервер безопасно использует локальное JSON-хранилище в каталоге `data/`.

## Чистый локальный запуск

```powershell
git clone https://github.com/hofmankz100-bot/ppr-control.git
cd ppr-control
npm ci
npm run check
npm start
```

После запуска приложение доступно по адресу:

```text
http://localhost:8080/
```

`npm run check` сначала собирает production-файлы, затем запускает модульные
и серверные тесты. Браузерные сценарии запускаются отдельно через
`npm run test:e2e` после установки браузеров по инструкции ниже.
Тесты используют изолированные временные данные.

После `npm ci` обязательно выполнить `npm run build` (или `npm run check`):
сборка также пересоздаёт браузерный импорт Word с исправленной XML-зависимостью.
Готовый файл из пакета Mammoth не используется без этой пересборки.

## Переменные окружения

Основные параметры перечислены в `.env.example`. Файл служит шаблоном и не
содержит настоящих паролей. Сервер читает локальный `.env`, если он существует;
значения, уже заданные в Render или оболочке, имеют приоритет.

Для обычной локальной разработки переменные окружения не обязательны.
Никогда не используйте production-строки подключения при запуске тестов.

## Основные возможности

- поиск оборудования по названию, участку и узлу, фильтр «Требуют внимания»;
- узлы оборудования;
- обход текущей смены и календарь ППР;
- чек-листы ТО, ТО-2, ТО-3;
- комментарии и отметка устранения;
- красная мигающая сигнализация по оборудованию при открытом замечании;
- подтверждение записи после сохранения в основной PostgreSQL, резервные зеркала;
- хранение состояния устройства через localStorage и IndexedDB;
- manifest и service worker для PWA.

## Документация

- `ROLES.md` — роли, базовые права и индивидуальные разрешения;
- `WORKFLOWS.md` — основные рабочие процессы и маршруты данных;
- `MODULES.md` — назначение клиентских доменных модулей.
- `docs/BROWSER_TESTING.md` — проверки в настоящих браузерах, мобильные профили,
  изолированные тестовые базы и известные ошибки.
- `docs/IMPROVEMENT_PLAN.md` — этапы изменений и критерии приёмки.
- `docs/DAILY_USE.md` — поиск, обход и работа при перебоях связи.

Для установки на iPhone или Android приложение нужно разместить на HTTPS-адресе.
После этого:

- iPhone: Safari -> Поделиться -> На экран Домой;
- Android: Chrome -> Установить приложение.
